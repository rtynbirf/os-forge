# СМОК-ТЕСТ образа и ковка как DAG (П44, issue #3)

## 1. Ковка как DAG

`forge/dag.json` — манифест шагов ковки с зависимостями, входами, выходами
и требованиями к инструментам. Супервизор `forge/dag_run.py` (std-only
Python) ставит pipeline на **идемпотентность-храповик**:

- шаг исполняется только если fingerprint его входов (sha256 от списка
  «путь:хеш») изменился либо выходы на диске расходятся с пломбами
  `forge/state.json`;
- повторный прогон на том же входе = **0 исполнений** и те же артефакт-хеши;
- подменённый артефакт обнаруживается и воспроизводится исходный результат;
- цикл/висячая зависимость в DAG = красный **до** любого исполнения;
- отсутствующий инструмент = честный ОТКАЗ (fail-closed), не имитация.

Машинная проверка механизма (живой прогон, без сети):

```bash
python3 forge/dag_run.py selftest
# DAG_CYCLE_TEST=PASS · DAG_DEP_TEST=PASS · DAG_FIRST_RUN=PASS
# DAG_IDEMPOTENT=PASS (повтор = 0 исполнений, хеши те же)
# DAG_TAMPER_REPAIR=PASS · DAG_INPUT_CHANGE=PASS · SELFTEST=PASS
python3 forge/dag_run.py plan     # план по настоящему dag.json
```

CI-воркфлоу `.github/workflows/forge-dag.yml` гоняет selftest+plan на
каждом пушe — свидетельство зелёности на main.

## 2. Смок-тест образа: контракт

| Параметр | Значение |
|---|---|
| Инструмент | `qemu-system-x86_64` (без графики, серийная консоль) |
| Вход | собранный ISO (`output/OSFORGE_debian_amd64.iso`) |
| Контракт | **boot до приглашения ≤ 120 сек** — маркеры загрузки (SeaBIOS → «Booting from CD-ROM» → ISOLINUX) на серийной консоли |
| PASS | ≥ 3 маркера за таймаут |
| FAIL/красный | таймаут исчерпан, маркеров нет → образ не загрузочный |
| Честный отказ | qemu не установлен → exit 3 с инструкцией, не имитация |

Запуск на машине с qemu:

```bash
DRY=0 bash запуск.sh сборка                      # ковка ISO
bash forge/smoke_boot.sh output/OSFORGE_debian_amd64.iso 120
```

Отчёт: `output/OSFORGE_debian_amd64.iso.СМОК-ОТЧЁТ.txt` (сырой лог: `*.СМОК.raw`).

Расширенный вариант (опционально): текст установщика виден на серийной
консоли, если на подсказке `boot:` передать `install console=ttyS0,115200n8`
(или собрать ISO с preseed-строкой `console=ttyS0`) — тогда критерием
служит приглашение установщика в логе. Базовый контракт выше — минимум,
который машина проверяет сама.
