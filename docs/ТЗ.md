# OS-FORGE — ТЕХНИЧЕСКОЕ ЗАДАНИЕ v0.1

> Карта должна приблизиться к территории. Пункт должен знать, почему работает только так.

## 1. Формализация задачи

```
N      = субъект = агент = человек (РОЛЬ, не индивид!)
         N — это роль «запускающий». Роль абстрактна: её может занять любой
         носитель. Индивид — конкретен: биография, голос, память. Батник
         обслуживает РОЛЬ, а не индивида. Не путать — это не одно и то же.

БАТНИК = самодостаточный автономный алгоритм действий. Один файл. При
         активации работает без присмотра. Ничего не требует предустановленного
         сверх самой ОС хоста.

КАРТА  = описание среды (железо + ОС), построенное ТОЛЬКО из фактов устройства.
         Закон: карта приближается к территории (реальности) или батник честно
         отказывается. Догадка = запрет.

СЕТЬ   = репозиторий пунктов (этот репо). Батник идёт сюда за инструментами
         и значениями, а не «искать, а всё пропало».

ЯДРА   = инструменты-навыки (cores/), которые батник добывает из репозитория
         ПО РЕШЕНИЮ: что решил — то и взял.

ISO    = артефакт: полная готовая ОС, актуальная на момент запуска, с пунктами,
         оптимально настроенными под конкретную конфигурацию (карту).
```

## 2. Семь стадий алгоритма (при активации)

| # | Стадия | Что делает | Чем фиксируется |
|---|--------|-----------|-----------------|
| 0 | АКТИВАЦИЯ | самопроверка хозяина (curl, powershell, диск) | ЖУРНАЛ |
| 1 | КАРТА | факты железа+ОС хоста: CPU, RAM, GPU, диски, сеть, UEFI, локаль | КАРТА.txt |
| 2 | РЕШЕНИЕ | по карте выбирает ветку алгоритма и набор ядер | ЖУРНАЛ |
| 3 | СЕТЬ | идёт в репозиторий за ядрами и активными пунктами каталога | ЖУРНАЛ |
| 4 | СБОРКА | добывает актуальную ОС, внедряет ответы/драйверы/настройки | ЖУРНАЛ |
| 5 | АРТЕФАКТ | выводит полный готовый ISO в место из КОНФИГА | ISO + хэш |
| 6 | ЖУРНАЛ | каждый такт записан в момент такта, не по памяти | ЖУРНАЛ.txt |

## 3. Законы (нарушение = батник лжёт)

0. **Ноль догадок.** Карта строится только из фактов устройства (CIM/WMI на
   Windows; /proc, lspci, lsblk на Linux). Нет факта — честное «НЕИЗВЕСТНО»
   с причиной. Выдумывать значение запрещено.
1. **Закон пунктов.** Каждый пункт каталога зафиксирован с «ПОЧЕМУ ТОЛЬКО ТАК»
   и «ПО ДРУГОМУ НЕТ». Активация пункта = раскомментировать строку `ACTIVE`.
   Пассивный пункт объясняет, почему он пассивен.
2. **Опасное пассивно.** Всё, что стирает диск/данные, по умолчанию помечено
   предупреждением и активируется осознанно запускающим.
3. **Честные русские отказы.** Если нельзя — отказ с причиной и точным
   «почему по-другому нет». Молчаливые сбои запрещены.
4. **Журнал в момент такта.** Не по памяти. Память врёт (шрам: сводка сессии
   соврала про несуществование готового прототипа).
5. **Хэш-пины на движущиеся вещи.** Чужие ветки пинятся по коммиту (Fido —
   по хэшу). У официальных источников образов — актуальность + проверка SHA256.
6. **Машина-слова ASCII.** Ключевые слова протокола (ACTIVE, PASS, STAGE,
   ACTIVE|id|keys|value) — ASCII: кодовые страницы cmd/PowerShell — шрамы.
   Человеческие тексты — русские.
7. **Ноль прав администратора на хосте.** Ни одна стадия не трогает систему:
   всё живёт в папке ВЫХОД. (Почему: монтирование образа, пересборка ISO и
   скачивание не требуют админа; DISM-интеграция требует — потому отвергнута.)
8. **Драйверы — встроенной механикой.** Папка `\Драйверы` в ISO + DriverPaths
   в autounattend: это механизм самого установщика Windows. Ноль DISM,
   ноль сторонних инструментов.

## 4. Грамматика каталога (формат пунктов)

```
# ── ПУНКТ: название ────────────────────────────────
# ПОЧЕМУ ТОЛЬКО ТАК: <причина>
# ПО ДРУГОМУ НЕТ: <почему альтернативы отвергнуты>
ACTIVE|<id>|<ключи соответствия карте>|<значение>|<примечание>
# PASS|<id>|<ключи>|<значение>|<почему пассивен>
```

- Строки `ACTIVE|...` — активные пункты: батник их исполняет.
- Строки `# PASS|...` — пассивные: документированы, не исполняются.
  Активировал — убрал `# ` в начале строки.
- В `<значении>` запрещён символ `|` (это разделитель грамматики).
- Ключи соответствия: `os=...`, `arch=...`, `class=...` — сопоставляются КАРТЕ.

## 5. Конфиг запускающего

Запускающий (N) правит ТОЛЬКО блок КОНФИГ в начале батника:
`VYHOD` (куда ISO), `CEL_OSI` (auto|win11|debian), параметры Windows-редакции,
учётная запись автоустановки, сухой прогон. Остальное — ядро, не трогать.
